# Contributing

Contributions should make the repository more useful as a **decision and methodology reference**.

## Good contributions

- add or update a recognized methodology;
- improve framework comparison;
- add a threat-informed workflow;
- add reporting or evidence guidance;
- add defensive-validation mapping;
- correct stale official references;
- improve structured metadata in `frameworks.yaml`.

## Avoid

- uncurated tool dumps;
- exploit collections;
- copied vendor marketing;
- unsupported threat claims;
- duplicate links without context;
- instructions that assume testing authorization;
- offensive content with no defensive or methodological value.

## New framework checklist

When adding a framework, include:

1. official name;
2. official source;
3. category;
4. problem it solves;
5. best use cases;
6. limitations;
7. how it complements existing entries;
8. last review date.

## Style

Prefer concise Markdown, tables and diagrams. Explain why something matters before adding another link.


## Catalog quality gate

Before adding a project to the core catalog, follow [docs/review-policy.md](docs/review-policy.md).

Every entry must identify its canonical upstream, type, domain, status and review date. New or uncertain projects belong in the research watchlist until their provenance and maintenance state are verified.
